# Material Inbox and Information Bank

“材料收件箱”是 CV Studio 的 zero-to-organized 入口。它接受一次混合输入，而不是要求用户预先判断内容属于哪一类。

## 输入与确认

- 文本框保留普通粘贴文字；富文本粘贴的 HTML 会和纯文本一起保存在原始提交中。
- 剪贴板图片与通过选择器 / 拖放加入的文件保存为本地来源附件。单个附件上限 5 MB，总计上限 16 MB；附件是 provenance，不是银行里的知识本体。
- PDF.js 会先在本机从最多 20 页提取文字，并为前 3 页生成视觉预览。文字型 PDF 可以直接进入本地分类；扫描 PDF 的页面预览可交给配置好的视觉模型理解。
- OpenAI、Anthropic 或 Hermes 使用与 Resume Agent 相同的全局配置。远程分类会接收文字、可读取文本文件 / PDF 的提取内容，以及最多 8 张图片或 PDF 页面预览。
- 本地模式不声称可以读取图片。没有可读文字的图片或扫描 PDF 会标为“未提取”；如果它确实是用户本人的头像，可以在审核卡中明确勾选“设为个人照片”，否则必须启用视觉模型、由用户补充可靠转录 / 描述，或移除。只有 `fields.profile.isPhoto === true` 且关联 LaTeX 可稳定渲染的 PNG 或 JPEG 时，纯照片条目才允许入库。
- CV / 简历只被视为来源，不再作为一个完整 `cv` 条目入库。模型只会把事实拆成个人信息、项目经历、工作经历、荣誉和奖项、教育经历、专业技能、课外活动、社会实践、演讲和讲座、论文发表十类；旧版联系方式、个人简介、个人总结、照片和其他类目读取时归入个人信息。
- 模型输出不会直接入库。用户可以修改每个 segment 的分类、标题、摘要与提取内容，然后显式确认；服务端会再次拒绝没有任何可复用内容或结构化字段的条目。

## 本地数据模型

`.cvstudio-bank/bank.json` 保存三个层次：

1. `submissions`：原始文字、HTML、附件引用和时间；
2. `items`：用户确认后的 `job` 与 `personal` 提取结果、`extractionStatus`、个人信息类目与结构化字段；
3. `assets`：来源附件元数据，二进制内容位于 `.cvstudio-bank/assets/`。

信息银行使用“职位描述 / 个人信息”双列。点击任意列会把它平滑展开为主内容区，另一列收起为整列可点击的索引；系统开启 `prefers-reduced-motion` 时会取消过渡。每列可选择每页 5、10、20 或 50 条。个人信息按常用程度排列：个人信息、工作经历、项目经历、教育经历、专业技能、荣誉和奖项、课外活动、社会实践、演讲和讲座、论文发表。

搜索会在两列的全部记录中匹配标题、摘要、用户原文和结构化字段，不受当前展开列或分页限制；类别筛选包含职位描述和十个个人信息类目。每条记录都有独立复选框，全选与反选作用于当前搜索和筛选后的全部结果。选择会跨分页保留，用户可清空选择或一次批量删除；批量删除以单次银行写入完成，不会留下只删除一部分的中间状态。

银行卡片的精简状态是包含复选框、类别、标题和录入日期的单行；显式个人照片会同时显示圆形缩略图。展开后只显示可直接复制的用户原文，不重复结构化卡片或模型说明。从可见银行移除条目不会同时销毁原始 submission 或附件，便于后续恢复和审计。这个目录位于 App 的默认工作区数据根中，不放进用户当前打开的任意外部 LaTeX 项目。旧版 `cv` 条目读取时会作为个人信息显示；新解析不会再写入 `cv` 类型。

## CV generation

生成器只使用用户在信息银行中已经显式选中的条目。打开生成对话框后，个人信息与多个职位的选择都会锁定为只读摘要，不再出现第二套素材复选框或职位选择器。没有显式个人信息条目 ID 或选择为空时服务端会拒绝生成，不会回退到整库材料。缺少的信息保持为空，不会被规则层编造。服务端只会把显式 `isPhoto` 条目或旧银行中明确的 `personal.category === "photo"` 作为头像，普通截图、证书和作品图不会再被自动选为头像。

生成对话框提供四个带版式缩略预览、键盘可选的模板：

- `classic`：受 `geekplux/cv_resume` 启发的蓝色单栏时间轴，MIT，可显示照片；
- `awesome`：受 Awesome-CV 启发的红色紧凑单栏，LPPL-1.3c，不显示照片；
- `sidebar`：受 AltaCV 启发的 64/31 双栏与个人侧栏，LPPL-1.3+，可显示照片；
- `banking`：受 moderncv banking 风格启发的线性 ATS 版式，LPPL-1.3c，不显示照片。

这些是基于项目视觉和语义方向重新实现的 portable adaptation，不复制或打包上游 class/assets，也不增加 CDN 或浏览器依赖。所有模板使用 XeLaTeX/xeCJK；macOS 优先 PingFang SC，本机没有时使用 App 离线 manifest 已验证的 FandolSong 常规/粗体，拉丁文字在没有 Helvetica Neue 时沿用 LaTeX 默认字体。选择会保存在本地，下次生成继续使用。

“职位贴合率”提供五档：紧贴职位、高度贴合、平衡、轻度参考、完全不考虑职位描述。前四档会把所有已选职位作为排序和措辞依据；职位描述永远不是候选人事实，Agent 不得把要求改写成用户技能或经历。最低档会在服务端移除全部职位上下文，`source-data.json` 的 `targetJobs` 为空，生成 Agent 和规则模板都不会读取职位内容。没有选择职位时界面会自动锁定到最低档。

配置远程 Provider 时，专用 CV Generation Agent 会读取受限的 `source-data.json` 与基础 `resume.tex`，最多运行 16 轮，只能提议更新 `resume.tex`，并通过独立临时快照编译验证；它不能读取当前外部项目，也不能修改来源数据。`source-data.json.template` 是绑定的模板契约，包含布局、照片能力、支持/紧凑栏目、语义槽位和逐条 `itemPlacements`。Agent 必须保留现有宏、列结构与视觉层级；没有直接槽位时只能映射到语义接近的位置，非必要且无法自然安放的内容应省略，不能为职位描述凭空创建候选人事实。安全且可编译的生成修改会自动应用，因为这是用户主动创建的新项目。本地 Provider 继续使用确定性规则，按实际的准备、排序和编译步骤报告进度，不伪装成模型。通用 Resume Agent 的循环上限为 12 轮。

生成项目包含：

- `resume.tex`：所选模板的本地 portable edition；
- `assets/profile.*`：显式选中的个人照片（即使所选模板不显示，也保留用于换版）；
- `source-data.json`：本次生成使用的已审核结构化材料、模板契约、放置/省略计划，以及照片是否渲染；
- `TEMPLATE-SOURCES.md`：四个上游视觉参考、许可证与 Fandol 中文字体来源；
- `README.md`：所选模板和数据边界说明；经典模板另含 `LICENSE.geekplux-cv.txt`。

上游模板通常依赖自己的 class、图标和特定系统字体。项目内置 Tectonic 的离线 bundle 不保证包含这些资源，因此 portable editions 只使用 App 已验证的基础 LaTeX 包，同时保留各自的信息层级和明确来源归属。

每次生成都会在 App 数据工作区的 `generated-cvs/<CV 名称>/` 下创建新的独立文件夹，不弹出路径选择器，也不覆盖当前 CV。服务端切换到新项目后，前端将它追加进持久化“我的 CV”项目库；用户可以继续用同一份素材针对不同职位生成多份 CV，在项目库中切换，并为每份 CV 保留独立源码、资源、主文档和 Agent 会话。

生成请求使用 NDJSON 流返回真实阶段：选择校验、规则准备、Agent 每轮工具调用、LaTeX 编译和工作区保存。对话框在生成期间保持打开并显示进度条，也可以显式停止请求；旋转状态动画遵守 `prefers-reduced-motion`。
